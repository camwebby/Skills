# Experiment Menu

Design experiments around the riskiest assumption first. Prefer reversible tests that produce behavioral evidence.

## Validation Ladder

| Step | Goal | Strong signal | Weak signal |
|---|---|---|---|
| Customer interviews | validate problem and workflow | repeated pain, real workaround, budget clues | polite interest |
| Smoke test | validate demand and message | qualified conversion with price shown | generic waitlist signup |
| Concierge or Wizard-of-Oz | validate workflow value | users complete the job, return, share data | demo praise |
| Paid pilot | validate willingness-to-pay | paid, renewed, expanded, or signed LOI | unpaid trial with no buyer |

## Experiment Types

### Problem Interviews
Use when problem severity or ICP is unclear.
Pass threshold examples:
- 10 of 15 target customers report the problem as frequent and costly
- 6 of 15 already use a workaround or pay for an alternative
Fail threshold examples:
- fewer than 4 describe the problem unprompted
- pain is mostly theoretical or infrequent

### Landing Page Smoke Test
Use when demand, messaging, or ICP channel is unclear.
Pass threshold examples:
- qualified conversion exceeds pre-registered threshold
- visitors understand the value proposition without explanation
Fail threshold examples:
- traffic converts only after heavy explanation
- conversions are unqualified or price-sensitive

### Price-Shown Waitlist
Use when willingness-to-pay is uncertain.
Pass threshold examples:
- qualified prospects click, book, or apply after seeing price
- buyer says which budget pays for it
Fail threshold examples:
- interest drops sharply when price appears
- no budget owner emerges

### Concierge MVP
Use when workflow value is uncertain and product is expensive to build.
Pass threshold examples:
- users return for repeated use
- users provide data/access and tolerate manual delivery
- clear time, money, or risk reduction is observed
Fail threshold examples:
- heavy hand-holding is required without repeat demand
- value depends on unrealistic customization

### Wizard-of-Oz MVP
Use when automation risk is high but the user experience can be simulated manually.
Pass threshold examples:
- users complete the target job without caring that backend is manual
- outcome quality can be delivered repeatably
Fail threshold examples:
- manual fulfillment reveals brittle edge cases or unacceptable costs

### Paid Pilot or LOI
Use when budget and sales motion are key risks.
Pass threshold examples:
- paid pilot, signed LOI, procurement step, or renewal commitment
- buyer accepts clear success criteria and timeline
Fail threshold examples:
- prospects request free pilots indefinitely
- decision makers avoid budget discussion

### Outbound Channel Test
Use when GTM clarity is weak.
Pass threshold examples:
- reply and meeting rates exceed pre-registered thresholds with target ICP
- replies mention the exact pain or current workaround
Fail threshold examples:
- responses are from wrong personas or are curiosity-only
